NexoBot Roadmap / Structure Overview

Goal
- Keep this as a practical map of the codebase.
- Show main folders and important files only (not every file).

Root
- package.json                -> scripts (build, start, dev, typecheck, test, migrate, backup), dependencies
- tsconfig.json               -> TypeScript config (strict, NodeNext, src -> dist)
- Dockerfile                  -> multi-stage build (tsc) + slim runtime (node dist/app.js)
- README.md                   -> setup and usage docs (German)
- docs/COMMAND_MIGRATION.md   -> old -> new command mapping (99 -> 36)
- tests/                      -> node:test checks (npm test, run via tsx)
- lavalink/                   -> Lavalink node list and local Lavalink config
- logs/                       -> runtime log output
- dist/                       -> compiled output (git-ignored)

src/
- app.ts                      -> NexoBot client, startup, web server (/health, /ready), cron jobs
- types/index.ts              -> shared types (Command, BotEvent, handlers, Client augmentation, GuildConfig)

- commands/                   -> slash commands by category folder
  - <Category>/<name>.ts      -> top-level command (router or standalone)
  - <Category>/modules/       -> subcommand implementations (old top-level commands live here)
  - Economy/ (eco, economy), Music/ (music), Giveaway/ (giveaway), Leveling/ (level, rank),
    Tools/ (tools), Utility/ (info, todo, report, wipedata), Core/ (bot, help, commands, configwizard),
    Fun/ (fun, count), Welcome/ (welcome), Verification/ (verification, verify), Ticket/ (tickets, ticket),
    Moderation/ (ban, kick, mod, channel, msg, cases), Community/, Birthday/, JoinToCreate/,
    Logging/, Reaction_roles/, Search/, ServerStats/

- config/                     -> centralized configuration
  - bot.ts                    -> single source of truth for theming/colors and core bot config
  - env.ts                    -> zod schema for environment variables
  - commands/legacyCommandMap.ts -> old command names -> new paths (access, prefix, help, docs)
  - commands/                 -> aliases, categories, prefix restrictions
  - database/                 -> Postgres config and schema version

- events/                     -> Discord event listeners (interactionCreate, messageCreate, ...)
- handlers/                   -> component handlers and loaders
  - loaders/commandLoader.ts  -> loads and registers slash commands
  - loaders/events.ts         -> event registration
  - loaders/interactions.ts   -> button/select/modal registry
- interactions/               -> button, modal and select menu handler modules
- services/                   -> business logic + data operations
- utils/                      -> shared helpers
  - commandRouter.ts          -> builds consolidated commands from old command modules
  - database.ts               -> facade re-exporting database modules
  - database/wrapper.ts       -> DatabaseWrapper, typed key-value API
  - errorHandler.ts, logger.ts, embeds.ts, interactionHelper.ts, ...
- scripts/                    -> maintenance scripts (backup, restore, migrate), run from dist/scripts

Database
- PostgreSQL (primary) with in-memory fallback for development
- Graceful degradation when PostgreSQL is unavailable

Notes
- Modular by feature area: commands -> handlers -> services -> utils
- User-facing texts are German; code, comments and logs are English
